## 1. 目标与全程约束

最终案例包中的每个有意义对象都应能独立移动。移开上层对象后，下层对象不应出现无法解释的空洞或明显截断。原图合成结果属于事实证据；生成像素属于明确标注的推测。

全程保持以下约束：

- 生产运行期间 `design.json` 与版本化素材是唯一事实来源；最终发布后这些临时文件必须删除，只保留 PSD 与实际外部依赖。
- `directExtractionTargets` 的原图完整提取层不可修改，只有 Alpha 边缘存在背景污染时允许做局部颜色净化。
- `completionTargets` 的交付层必须等于完整 Image 候选去背景结果；不得裁成隐藏区域，也不得叠加原图可见残片层。
- 遮挡者必须位于被遮挡对象上层。
- 背景生成只能改变被移除前景遮住的区域。
- 文字必须逐字保持原文和原语言。
- 每个通过决定都必须有证据和报告。

### 1.1 一次过生产策略

一次过依靠前置判断和逐阶段阻断，不依靠复用或事后修补：

1. 冻结源图和任务上下文，生成允许证据清单；禁止旧案例产物和本轮派生图串入当前案例的识别上下文。
2. 先完成多模态完整对象识别、实例身份、展示状态、附着部件、全部文字/品牌标识和组成关系，再开始任何分割；遮挡关系只在完整实例之间判断。低对比半透明品牌字、注册标记和小号英文必须在此时形成带原文、位置、透明属性、覆盖对象和层级的正式实例，不能留给后续阈值算法临时发现。
3. 每一阶段只消费上一阶段已通过的产物；失败立即停止，不能带病进入补全、组装和 PSD 导出。
4. 同类实例分别生成、分别验收。计算时间和调用成本不能作为复用对象像素或跳过门禁的理由。
5. 最终验收同时检查原位重合成和对象移开状态，避免“原位看起来一样、移动后才暴露错误”。

### 1.2 唯一流程权威与零旧产物启动

- 生产规则仅来自 `SKILL.md`、`pipeline.md`、`contracts.md`、`qa-gates.md` 和 `project-implementation.md`。其他项目文档、旧案例、旧脚本配置、旧报告和旧产物不能成为流程依据或视觉证据。
- 开工输入必须由调用方明确给出；不得打开案例目录中的候选图片、预览或旧报告来猜测源图。输入不明确时阻断并询问。
- 任何案例每次运行都从干净目录开始：保留明确指定的当前原图与用户真实参考，删除当前案例此前产生的全部其他内容。禁止查看、解析、哈希、预览、备份、迁移或缓存旧产物。
- 清场只允许枚举路径与读取删除所需的基础文件元数据。不得查看其他案例；不得删除其他案例。清场完成后生成本轮全新的初始化报告与证据清单。

## 2. 输入预检

1. 从调用参数接收唯一主源图和用户真实参考；若输入不明确则阻断，禁止查看案例目录内容来猜测。
2. 在任何视觉读取前清除当前案例旧产物，只保留明确输入；禁止备份、归档、迁移或查看被删除内容。
3. 生成 `验收/run-initialization-report.json`，记录运行 ID、保留输入、仅路径级删除清单、零旧产物查看/保留、零其他案例查看和固定流程权威来源。
4. 确认唯一主源图保持不变。
5. 根据 EXIF 方向生成规范化参考图。
6. 把工作副本转为 sRGB，同时保留原始色彩配置记录。
7. 记录宽高、DPI、颜色模式、透明通道、SHA-256 和文件大小。
8. 检测低分辨率、模糊、JPEG 块效应、过曝和透明度歧义。
9. 生成 `验收/input-evidence-manifest.json`：`allowedEvidence` 只列当前主源图与用户明确提供的当前任务真实参考，并记录路径、用途和 SHA-256；把其他案例目录和本轮后续派生预览模式列入 `forbiddenEvidencePatterns`。
10. 生成 `验收/input-preflight.json` 与 `source-reference.png`。`source-reference.png` 是当前源图的规范化副本，只能在其源哈希已登记时使用。
11. 图片无法解码、尺寸非法、存在解压炸弹风险、质量低于任务阈值，待分析文件不在 `allowedEvidence`，或初始化报告无法证明零旧产物查看/保留时直接阻断。

代码、Schema、模型和命令可以作为执行工具复用，但不能定义另一套生产流程；流程只以本 skill 文档集为准。视觉结论不能复用。不得打开其他案例的拆分总览、蒙版、坐标计划、候选图、验收图或 PSD，也不得保留或打开当前案例上次运行的任何产物。

## 3. 语义清单与 OCR

### 3.1 对象单位

对象必须同时满足“可独立操作”和“语义完整”：

- 服装保持完整，不能因为图案可分割就把服装切碎。
- 腿部保持完整；袜子、鞋子需要独立编辑时，可作为腿部对象的子层。
- 贴纸及其附着描边、尾巴、底座应保持为一个完整对象。
- 动作线确实属于角色动作时与角色一起移动，否则作为独立装饰层。
- 原生营销文字与栅格艺术内容分开；没有证据时，不把商品纹理或 Logo 图形识别成可编辑营销文字。
- 先确定顶层完整对象，再分析对象内部的文字、图案和可编辑子层。两个彼此分开的完整图形即使内部有大量视觉叠放，也不因此触发对象补全。

在调用 SAM2、抠图、OCR 排版重建或 Image 模型前，先生成 `object-integrity-plan.json`。该计划必须把数据分成两类记录：

- `instances`：后续可分割、可补全、可建 PSD 父组的完整对象；
- `components`：衣领、领带、袖子、背带、挂带、纽扣等完整性检查项，只能为所属实例提供提示和验收证据。
- `mutuallyExclusiveWith`：与当前实例容易混淆但必须排除的其他实例或组件；相交、贴合、同色均不能共享源像素。

计划必须由当前源图重新分析得到，写入 `semanticPlanOrigin: "current_source_fresh_analysis"`、`copiedFromPriorCase: false` 和本次实际读取的 `evidenceSha256`。旧计划只能用于测试兼容性，不能作为新任务语义输入；检测到旧对象键、旧坐标、旧提示或未授权视觉哈希时，本阶段失败。

实现代码必须只遍历 `instances` 创建输出。即使内部算法分别探测多个 `components`，也必须先在内存中组合成完整实例候选并通过组成部件召回检查；禁止保存、展示或交付破碎组件候选。门禁只是兜底，任务规划本身不得主动创建已知错误的对象单位。

同一首轮计划还要生成兼容命名的 `textGraphics`。它逐项登记普通营销文字、艺术字、文字型 Logo、低对比半透明品牌字、注册标记、小号英文及真实非文字符号的原文、四边形位置、透明/混合属性、所在材质、覆盖的完整实例和层级。字段名不代表允许输出文字图形层：凡能读取为字符串者必须进入唯一原生文字层；真实非文字符号才进入图形分支。

### 3.2 实例身份、服装状态与禁止复用

同一商品类别不等于同一图像实例。每个实际出现位置都记录：

- `instanceId`：当前画面内唯一；
- `productFamily`：只表示商品/款式家族，可供语义参考；
- `wearState`：`worn`、`unworn` 或可验证的其他状态；
- `displayState`：`on_person`、`flat_lay`、`hanging`、`mannequin`、`packshot` 等；
- `viewpoint`：正面、背面、侧面、细节或当前可见视角；
- `poseDeformation`：是否受人体、重力、折叠或摆放方式形变；
- `reusePolicy`：默认 `forbidden`；
- `observedPixelHash`、`hiddenSupportMask` 与 `attachedComponents`。

以下任一项不同即按独立实例处理：位置、穿着状态、展示状态、正反面、视角、姿态、褶皱、透视、光照、遮挡关系或可见范围。穿着实例只能看到当前身体姿态支持的表面，不能用未穿着平铺商品的完整像素替换。允许共享颜色、材质、款式和结构描述作为提示参考，不允许共享像素、Alpha、几何、蒙版或生成结果。

精确复用只适用于能够证明为源图中像素级相同的重复元素。报告必须保存匹配哈希、允许的刚性变换、差异图和审批状态；否则独立分析、独立分割、独立图像编辑调用、独立保存和独立验收。

### 3.3 视觉语言分析

要求视觉语言模型为每个候选对象给出：

- 名称与稳定键；
- 类别和语义描述；
- 粗区域或多边形；
- 原图可见部件；
- 可能被遮挡的部件；
- 候选父组及附着关系；
- 可编辑角色；
- 可能的遮挡者和证据；
- 不确定性与复核说明。

模型结果只是结构建议，不是最终蒙版，必须用原图像素进行验证。

### 3.4 文字、Logo 与透明品牌标识契约

为每个可编辑文字区域记录准确 Unicode 内容、换行、阅读顺序、四边形范围、估计样式、旋转、语言/文字系统和 OCR 置信度。关键文字至少采用两次 OCR，或一次 OCR 加一次视觉语言复核。

严禁翻译。例如 `Dance Time!` 不能变成 `舞蹈时间！`。大小写、空格、标点和换行都是原始数据。

另外扫描低对比、半透明、重复、跨材质覆盖和带注册标记的品牌内容。结合屏幕方向、透视、重复形式、透明度和跨对象覆盖关系，区分营销文字、覆盖式水印、服装印花、实体标签与 Logo。相同内容出现在不同位置仍是不同放置实例，必须分别记录和建层；凡能读取为字符串者即使字体或效果无法完全匹配也必须保留为原生文字层并记录近似/缺失警告，禁止保存透明栅格文字/品牌层。只有不构成字符串的真实符号 Logo 才可保存透明栅格图形及 OCR/分类元数据。

透明品牌标识是首轮阻断项。必须同时执行整图观察和重叠切片观察，并用多模态模型、OCR、局部对比增强、边缘/重复形式证据交叉复核。对主文字、英文副标、Logo、`®/™` 等注册标记和每个重复放置位置分别计数。任何疑似品牌残留未映射到 `textGraphics`，或登记数量与视觉复核数量不一致，首轮计划都不得通过。

透明文字是否使下方对象进入补全，取决于它是否已在首轮计划中作为独立 `textGraphics` 实例被识别、定位，并通过像素证据确认覆盖关系。未登记的“隐形前景对象”不能出现在遮挡图中。若看见疑似半透明覆盖痕迹却无法确认其身份或范围，记录 `unresolvedOcclusion` 并停在本阶段修正识别；不得一边漏掉透明字，一边凭空为下方上衣调用 Image。

## 4. 场景结构与遮挡图

### 4.1 关系分类

- `contains`：图层组包含子层。
- `attachedTo`：两个可见部件需要一起移动，但像素可以分开。
- `occludes`：一个对象在视觉深度上遮挡另一个对象。

`contains` 不能自动证明前后层级。

对象内部的文字、印花、描边、按钮图案、插画元素或同一移动单元中的部件，优先表达为 `contains`、`attachedTo` 或对象内部子层。只有两个不同完整对象在画面深度上互相遮住，才建立 `occludes`。边界接触、距离很近、包围框相交或同一图形内部的排版叠放都不足以证明遮挡。

### 4.2 固定判断顺序与补全目标

必须按以下顺序执行：

```text
多模态识别完整对象
→ 确认每个对象的组成部件与移动单元
→ 只在不同完整对象之间筛选空间相交候选对
→ 用轮廓终止/T 形交界/深度证据确认 occludes
→ samVisibleTargets = instances
→ completionTargets = unique(occludes.behind)
→ directExtractionTargets = instances - completionTargets
→ 对全部 samVisibleTargets 执行 SAM 原图可见像素提取
→ 仅对 completionTargets 生成独立 Image 完整透明对象层
```

`occlusionEdges`、`backToFront` 和三个目标集合必须写入并通过 `object-integrity-plan.json`，在任何对象级 SAM 或 Image 调用之前完成并冻结。`samVisibleTargets` 必须等于全部完整实例；`completionTargets` 是其中需要追加 Image 的子集；`directExtractionTargets` 与 `completionTargets` 互斥且并集等于全部实例。后续 `occlusion-graph.json` 只能是该首轮计划的派生快照，不得重新推断或改写层级。禁止从局部色块、文字压在底形上、对象内部线条交叉或包围框重叠直接推导 Image 补全。没有任何 `occludes` 边时，`completionTargets` 为空，跳过图像编辑模型，并生成空列表通过报告。

每条 `occludes.front` 必须能解析到 `object-integrity-plan.json` 中已登记的 `instances`、`graphics` 或 `textGraphics` 键；`behind` 必须是完整实例键。任何悬空键、未识别前景、未归属覆盖痕迹或低置信遮挡都必须在分流前阻断。

默认 `reconstructionMode` 为 `semantic_complete_layer`。在该模式下不得把 `directExtractionTargets` 改送 Image；这些无遮挡实例使用唯一的 SAM/Matting 原图完整提取层。`completionTargets` 则以去背景后的完整 Image 候选作为唯一交付层，不叠加源图可见残片。

### 4.3 遮挡证据优先级

按以下可靠性顺序判断：

1. T 形交界与轮廓在重叠边缘终止。
2. 同一纹理或轮廓在遮挡者两侧连续出现。
3. 光照、阴影与接触关系。
4. 人体、服装或产品结构的一致性。
5. 通用语义常识。

为每条遮挡边记录证据和不确定性。不能套用“上衣永远盖住裤子”等固定规则；当前图片的可见衣摆关系优先。

### 4.4 图有效性

`occludes` 必须构成有向无环图。拓扑排序得到从后到前的 PSD 顺序。出现环时先重新核对关系；如果图片确实存在前后交错，只拆出表达交错所需的最少前/后渲染子层，并继续保留一个完整语义父对象。

## 5. 全部完整对象的源图可见像素分割

本阶段处理全部 `samVisibleTargets`。对 `directExtractionTargets`，SAM/Matting 输出是完整对象 Alpha；对 `completionTargets`，输出只标记原图中实际可见且属于该对象的像素，必须记录 `scope: "visible_only"`，不能声称是完整轮廓。

首轮识别出的可编辑文字不作为 SAM 目标，直接进入独立原生文本框分支；这包括艺术字、文字型 Logo、半透明品牌文字和注册标记。只有不构成字符串的真实符号 Logo、蝴蝶、插画、图标等非文字图形才走图形专用提取；被遮挡时登记为完整图形实例并纳入 `samVisibleTargets` 与 `completionTargets`。前景原生文字的几何/透明覆盖蒙版和非文字图形 Alpha 在验收后可以成为更深对象的遮挡证据，但不能裁剪 Image 完整候选。

### 5.1 候选生成

一张图可以只计算一次无语义偏向的 SAM2 图像特征。首次进入本阶段不得复用旧运行或其他案例的任何对象级结果；同一运行因 SAM 证据触发语义计划修订时，只有通过 `sam-revision-plan.json` 证明完全不受影响的当前运行结果才可复用。`object-integrity-plan.json` 及其版本/哈希在每个 SAM 修订轮次进入前冻结；同一版本内的紧/宽两种边界策略都只能处理同一完整实例，不能改变对象身份、组成部件、组件归属、互斥关系、遮挡关系或层级。

每个 `samVisibleTargets` 实例先执行一次原收紧逻辑，并通过以下提示生成多组紧候选：

- 从高置信度内部区域和不同语义部件采样正提示点；
- 在相邻竞争对象内部放置负提示点；
- 带扩展余量的粗边界框；
- 可选的粗多边形或先验蒙版；
- 对自动发现的细小附属结构、孔洞、尾巴、带子、肢体及语义相关分离部件补充提示。

不得只根据模型最高分直接接受候选。紧候选若已经满足完整性和所有权门禁，立即接受并结束当前实例，不得再执行宽松补齐。

### 5.2 候选评分

综合以下归一化指标：

```text
总分 = 模型置信度
     + 提示点命中率
     + 可见部件召回率
     + 边缘强度
     + 原图连续性匹配
     - 排除对象泄漏
     - 无法解释的连通块惩罚
     - 裁切边界惩罚
```

不能维护一个永久的“具体形状清单”。语义部件提示必须根据当前图片的对象清单动态生成。

候选选择必须先通过非对称所有权门禁，再比较总分：

```text
第一优先级：objectOmissionPixels == 0
第二优先级：foreignObjectLeakPixels == 0
第三优先级：全部 attachedComponents / 外沿探针通过
第四优先级：backgroundHaloOwnership == verified_bottom_background_only
最后才比较：模型分、边缘质量、紧边程度
```

“少提取一点对象”绝不比“多带底层背景”更优。粗多边形、box 和 ROI 是提示与搜索走廊，不得硬裁掉模型已经识别出的外沿；应在对象外沿之外保留背景安全带，并用竞争实例负提示与排除 Alpha 防止吸入其他前景对象。`backgroundHaloPixels` 的数量和最大宽度必须记录，但只要所有余量都能证明属于最底层背景，就不构成失败或再次收紧理由；无法证明所有权时阻断。

### 5.3 Alpha 精修

1. 在选中二值蒙版边缘建立前景/背景三分图。
2. 运行 Alpha Matting 或同类柔边算法。
3. 只在确有背景串色情况下净化边缘颜色。
4. 原图存在毛发、薄纱、烟雾、玻璃等半透明结构时应保留。
5. 把输出裁到 Alpha 最小边界，并同步更新 `design.json` 中的位置框。

## 6. 全部源图可见像素验收与遮挡蒙版冻结

本阶段验收全部完整实例的源图可见像素，以及文字/图形专用分支的真实提取层。对有遮挡对象，只检查可见像素归属、邻居泄漏和柔边，不要求 SAM 推断隐藏轮廓。通过的前景 Alpha 立即冻结；后续可以用于锁定原图 RGB 和形成更深对象的 `frontOccluderSupport`，但不得用它裁剪 Image 的完整候选 Alpha。

### 6.1 几何检查

- 检测轮廓是否在没有真实终点证据的位置突然中断。
- 检测蒙版是否异常接触候选裁切边缘。
- 比较疑似缺口两侧的轮廓方向和曲率。
- 检测孔洞是否异常闭合或打开。
- 检测分离连通块，并判断其属于对象、噪声还是另一个对象。
- 确认透明素材四条边均接触非零 Alpha，且不存在透明留白。

### 6.2 原图连续性检查

检查蒙版外侧的窄带。如果颜色、纹理、描边或边缘方向从蒙版内部连续延伸到外部，且没有遮挡关系解释，蒙版很可能缺失。反之，候选内部出现邻居纹理连续流入，说明存在泄漏。

完整性误差采用非对称处理：外侧窄带中仍属于当前对象的像素一律计入 `objectOmissionPixels`；候选多出的像素只要能映射到最底层背景且不接触任何其他前景 Alpha，就计入可接受的 `backgroundHaloPixels`，不设基于面积或宽度的阻断阈值。其他对象、文字或装饰的一个像素都不得作为安全余量。

### 6.3 多候选分歧

计算合理候选之间的差异。某个附属部件或轮廓附近分歧较大时，应标记为不确定区域，不能直接选择最紧的候选。

### 6.4 视觉完整性复核

把候选分别放在白、黑、中灰和棋盘格背景上，并叠回原图。要求视觉模型回答：

- 所有原图可见语义部件是否保留？
- 是否存在突然截断的轮廓？
- 是否误带相邻对象或背景？
- 分离连通块是否在语义上属于该对象？
- 对象单独显示时结构是否完整、可识别？

### 6.5 单次完整外沿补齐

只对紧候选出现 `objectOmissionPixels > 0`、外沿探针失败或 `attachedComponents` 缺失的对象执行一次补齐：

1. 继续使用原始全分辨率源图和已冻结的同一语义契约；紧候选只提供主体核心锚点，不能成为裁切后的新输入。
2. 保留主体核心正提示，沿原图连续边缘、缺失外沿和缺失部件增加正提示点。
3. 扩展搜索走廊但不硬裁最终候选；保留全部竞争对象负提示、`mutuallyExclusiveWith` 和排除 Alpha。
4. 以“主体核心 + 完整外沿”模式重新提示 SAM 一次，并在该次产生的多候选中按硬门禁选择。
5. 要求对象身份与组成关系不变、`objectOmissionPixels == 0`、全部必含组件/外沿探针通过且 `foreignObjectLeakPixels == 0`。只多出经验证的最底层背景时直接允许通过。
6. 该对象的补齐调用次数必须为 1；若仍缺失、包含其他对象或破坏语义关系，立即阻断，不得第三次 SAM、循环扩边、事后像素修补或形状特例。

若证据表明首轮 AI 语义计划本身需要修正，只能返回首轮分析，生成具有新版本和新哈希的计划并全局重新验证对象清单、遮挡图、`backToFront` 和三个目标集合；SAM 阶段不得静默拆分、合并、改名、转移组件或重算层级。随后先生成 `验收/sam-revision-plan.json`，再从 SAM 前重启受影响对象闭包：

1. 以新增、删除或语义变化的对象，变化遮挡边的存续端点，以及目标分类发生变化的对象为种子。
2. 把正负提示、ROI、组成/附着部件、互斥集合、竞争对象、排除 Alpha、像素所有权或 `frontOccluderSupport` 发生变化的对象加入集合。
3. 沿互斥关系、空间重叠和遮挡支持依赖传递扩展，直到集合稳定；删除对象本身不再执行 SAM，但所有受其竞争/排除/所有权影响的存续对象必须进入集合。
4. 集合内对象从新的 tight pass 开始，继续读取原始全分辨率源图；“局部”只表示对象任务局部，严禁裁切局部图片作为新输入或硬裁最终 Alpha。
5. 集合外对象只有在源图/规范化/坐标、模型/检查点、对象级语义契约、提示计划、竞争集合、排除输入、输出 `scope` 与像素所有权全部未变，并已针对新计划重过完整性/互斥门禁时才能复用；否则并入集合。无法证明时重跑全部 `samVisibleTargets`。
6. 源图、规范化、模型/检查点及编码配置哈希一致时复用 SAM2 全图编码；任一变化则重新编码并重跑全部对象。
7. 增量结果与复用结果合并后，重新执行全局像素所有权、前景泄漏、遮挡图、目标集合和可见 Alpha 并集检查。受影响的 Image、背景、design、PSD 与 QA 按输入哈希失效，不能沿用陈旧下游产物。

### 6.6 未归属像素与附着部件

- 不得把分割后的残余像素按距离强制归入最近对象，也不得把未知区域塞入背景以追求覆盖率。
- 对无法确认归属的像素建立 `unassigned`/`needsReview` 记录并阻断；只有语义证据和边界证据同时通过后才能归属。
- 对 `attachedComponents` 逐项计算可见召回率。背带、提手、挂带、动作线、玩偶附件、纽扣、标签、透明品牌字样等任何一项缺失都不能通过。
- 对 `mutuallyExclusiveWith` 逐项计算误归属率并执行实例掩码互斥；任何其他对象的完整部件被吸入当前实例都必须阻断。细长部件必须结合走向、端点、连接对象和局部 ROI 判断，不能只按颜色或连通性归属。
- 如果多个部件在当前设计中构成一个整体移动单元，保留一个语义父对象；只有明确需要独立编辑时才建立子层，不能因分割方便把一体对象拆散。

## 7. 有遮挡对象的 Image 完整 Alpha

本阶段不是所有对象的固定步骤。进入条件是 `completionTargets.length > 0`。每个目标必须能追溯到至少一条已验收的 `occludes` 边，且目标是该边的 `behind` 节点。

对每个目标发起独立 Image 任务，要求返回该状态、视角和姿态下的完整对象，并置于透明背景或约定的纯色键背景。该目标在第 5 阶段已经有且只能有一份 `visible_only` SAM/Matting 结果，仅用于提示与验收候选；候选通过后禁止再次运行第二次 SAM、语义抠图、源图残片覆盖或用可见残片蒙版裁剪完整候选。

任务数量按去重后的 `completionTargets` 计算，不按 `occludes` 边数计算。同一件上衣被多个透明文字实例覆盖时，先合并这些已验收前景层的 Alpha，再为该上衣创建一个 Image 任务；候选重试必须显式废弃旧任务或标记父任务，最终只能接受一个结果。

若 `completionTargets.length == 0`：

- 禁止调用 Image 补全模型；
- 禁止创建空白、占位或伪补全图层；
- 写出 `objects: []`、`imageEditRequired: false`、`imageEditCallCount: 0`、`skippedReason: "no_inter_object_occlusion"`；
- 直接进入背景重建与设计组装。背景恢复是独立任务，不得伪装成对象补全。

### 7.1 从前到后的处理顺序

把 `backToFront` 逆序遍历：先验收最前方无遮挡对象并冻结其 Alpha，再处理被它遮挡的对象。一个对象即使自己属于 `completionTargets`，其完整 Alpha 一旦通过，也可继续作为更深对象的前景遮挡蒙版。这样每一层的隐藏区域都由已经确认的前层决定，而不是事后猜测。

### 7.2 事实与推测分层

对被遮挡对象创建固定结构：

```text
完整对象组
└─ Image完整透明对象  # 唯一交付像素层；完整候选 Alpha 与 RGB
```

不得同时保存或交付“原图可见像素”子层。对象组只是语义容器，不参与拼贴；唯一像素层本身就是完整对象。

### 7.3 隐藏区域证据

综合以下信息估计不可见结构：

- 可见轮廓进入遮挡者时的切线方向；
- 轮廓在遮挡者另一侧重新出现的位置；
- 对称与重复结构；
- 姿态、人体、服装或产品结构；
- 缝线、纹理方向和材质行为；
- 遮挡边缘与深度关系；
- 案例提供的其他视角图片。

隐藏支撑蒙版用于提示 Image、证明为何需要补全和执行原位遮挡 QA，应尽量保守；它不是交付素材裁剪蒙版。禁止用它把已验收的完整候选裁成只剩隐藏区域的碎片。

### 7.4 图像生成、单次转 Alpha 与真实性合成

使用 Image 2.0 或配置的图像编辑模型执行局部补全：

- 输入原图局部、可见对象层、隐藏支撑蒙版、遮挡者蒙版、语义描述、轮廓延续引导和材质/颜色参考；
- 生成多组候选；
- 没有可靠来源时禁止生成文字、Logo、标签和包装关键信息；
- 可见区域必须处于生成保护区之外；
- 能获取时记录种子、供应商、模型和提示词版本。

每个 `instanceId` 必须发起独立的图像编辑任务，使用当前实例自己的可见像素、姿态、遮挡者和隐藏支撑蒙版。不得把另一个实例的平铺、穿着、正面、背面或细节结果复制、缩放、变形后使用。

任务创建时立即绑定 `instanceKey` 与唯一 `generationTaskId`，并写入候选注册表。禁止根据文件时间、缩略图顺序、相似外观或人工猜测把输出映射回实例。图像模型输入只允许本次源图和用户明确提供的真实参考；旧 PSD、旧案例结果、拆分预览、候选总览、差异图和移动状态 QA 图禁止作为参考再次输入模型。

候选一旦通过 `wearState`、`displayState`、视角和组成完整性检查，后续出现破洞、错位或错误露出时，先修正坐标映射与全局层级。不得把合成错误误判为候选错误而盲目重生成。对补全目标，第 5 阶段的 SAM/Matting Alpha 只用于候选验收，不能成为 PSD 子层，也不能裁定、覆盖或裁坏 Image 完整候选。

候选先检查 `wearState`、`displayState`、视角、姿态和组成完整性。通过后只允许执行一次确定性的透明背景/键色背景转 Alpha 与坐标对齐；若模型原生返回 Alpha，这一次操作仍负责解码、规范化和记录。`alphaConversionCount` 必须为 `1`。此后 `semanticSamCallCountAfterCandidateAccepted` 必须为 `0`。

通过候选的 Alpha 与 RGB 是该被遮挡对象的最终像素依据。PSD 素材必须使用：

```text
generatedCompleteAsset = generatedCandidate ∩ candidateAlpha
deliveredPixelLayersForInstance = [generatedCompleteAsset]
```

`observedVisibleAlpha` 和 `frontOccluderSupport` 只保留在中间报告中。`generatedCompleteAsset.alpha` 必须与规范化后的 `candidateAlpha` 一致，候选 RGB 除键色边缘去色外必须原样保留；不能再与任何隐藏支撑、可见残片或遮挡者蒙版求交，也不能叠加源图可见层。中位色、纯灰、纯背景色和手绘色块只能作为调试可视化，不能作为完成素材或进入 PSD。

若最终合成出现破洞、错误露出或轮廓被截断，先检查是否错误加入了源图残片层、是否裁剪了候选，以及首轮图层顺序是否正确。只有候选自身的状态、视角、姿态或组成不符合实例计划时才允许重新生成；不得以第二次 SAM、隐藏支撑裁剪或源图拼贴代替流程纠正。

源图已有的半透明品牌字使用首轮 `textGraphics` 记录逐字创建唯一原生文字层，并在该层设置透明度、混合模式及可支持的文字/图层效果；其下方被覆盖的衣料单独进入补全。禁止提取、生成或交付独立字形 Alpha、图片层、图形层或栅格效果子层；无法完全复现的外观记录近似/缺失警告。

### 7.5 补全复核

检查每个候选：

- 与可见对象的几何和轮廓是否连续；
- 材质、颜色、纹理尺度、光照和透视是否一致；
- 人体或产品结构是否合理；
- 单独显示时是否与接受的完整 Image 候选去背景结果一致；
- 同一实例是否错误存在第二张源图残片或补丁层；
- 是否出现重复肢体、缝线、边缘或图案；
- 恢复原位后是否正确被遮挡者盖住。

候选必须通过后才能接受，否则继续重试或阻断。

### 7.6 原位重合成约束

所有对象恢复原始坐标和层级后，每个完成实例必须仍只有一张完整透明像素层，并位于首轮计划指定的遮挡者后方。移开遮挡者或单独查看该层时，应与接受的 Image 候选去背景结果一致；若出现洞口碎片、源图拼贴或第二张像素层，立即阻断。

## 8. 背景重建

根据全部前景可见蒙版的并集，区分已知背景和缺失背景：

- 纯色/渐变：拟合后确定性渲染。
- 重复纹理：估计周期并做纹理延展。
- 照片/插画：只在带羽化的恢复区域内生成式修复。
- 恢复区域外的已知背景像素必须完全保留。
- 清除被移除对象的残影、描边和属于对象的阴影。
- 原始生成候选、净化候选、恢复蒙版、最终背景和报告全部保留。
- 背景只从已验证的背景像素、背景模型或明确恢复区域推断；未归属残片不能强制交给背景。
- 对象逐个移开后检查恢复区域，不允许残留前景颜色、轮廓、透明字、阴影、补丁边界或被错误填入的邻居像素。

## 9. 文字与形状重建

### 9.1 文字

用原文创建原生文字节点。只从已授权字体中匹配，并通过 PostScript Name 和渲染轮廓比较选择字体；近似字体必须标记。编辑时保留原文字系统，前端和导出流程都禁止翻译及自动规范化。

每个可编辑字符串只采用一个原生文字层。艺术字的描边、立体、纹理和初始源外观只能通过同一文字层的文字样式、PSD 图层效果或内部像素缓存表达；内部缓存不得成为独立 `design.json` 节点、PSD 图层、图层面板条目或画布可选对象。原生文字无法表达的效果记录为近似或缺失警告，禁止为了保真额外建立包含该字形的栅格层、图片层、图形层或效果子层。

每个实际字符串、艺术字、文字型 Logo、透明品牌文字和注册标记按放置位置独立建立唯一原生文字层；纯符号 Logo 按图形类别另建层。可编辑字符串必须且只能交付一个原生文本框，也禁止把一整片标题、英文副标、中文副标和装饰字合并成一个大栅格块。只有不构成字符串的真实符号 Logo、非文字服装印花或实体图形标签才可按正确类别保留为栅格图形；不得把已经识别为文字的内容降级成图形。

### 9.2 形状

稳定的简单几何重建为矩形、圆形、线条或路径层。复杂插画保留为不规则透明像素层。不能为了声称“矢量可编辑”而接受噪声严重的自动描摹。

## 10. 设计组装

用已验收的素材生成唯一 `design.json`：

1. 默认隐藏的参考图组；
2. 重建背景；
3. 按遮挡图排序的语义对象组；
4. 位于证据支持层级的原生文字和形状；
5. 前景装饰与效果。

保存稳定 ID、准确位置、素材哈希、字体清单、来源引用、置信度和 `needsReview`。当前 Schema 无法保存的遮挡/补全信息放入标准旁路文件，并在图层树中用“可见/生成”子层表达；需要新增字段时必须正式迁移 Schema，不能偷偷写入被禁止字段。

## 11. PSD 导出

写入前生成能力计划。优先映射：

- 组 → PSD 图层组；
- 文字 → 原生文字层；
- 图片 → 支持时使用智能对象，否则用透明像素层；
- 形状 → 可靠时使用原生形状层；
- 蒙版 → 支持时使用图层蒙版，否则预裁透明图层；
- 不支持效果 → 带明确名称和警告的栅格效果子层。

从后到前写入，包含临时合成预览，使用原子方式保存到本轮临时工作区。最终发布前不得在案例目录保留历史 PSD；新 PSD 只有全部门禁通过后才能原子发布到独立交付目录。

## 12. 验收与交付

依次执行 Schema、素材/哈希/引用、Alpha 紧边、语义完整性、遮挡补全、背景、PSD 独立解析、原生文字、图层顺序和像素对比检查。严格遵守 `qa-gates.md`。

每个阶段通过后写报告并冻结其输入哈希。必须额外执行实例独立性检查、状态错配检查、`directExtractionTargets` 原图像素零差异检查、`completionTargets` 候选一致性与单层检查、附着部件完整性检查、透明品牌标识完整性检查，以及逐对象移开后的背景/补全检查。全局相似度高不能抵消任何局部门禁失败。

上述报告和视觉证明必须在本轮临时工作区中生成并完成验收，但不得进入最终交付。全部门禁通过后执行最终收尾：

1. 原子发布 `交付/final-layered.psd`。
2. 解析 PSD 的真实外部引用，只复制实际必需的字体（`.ttf/.otf/.ttc`）、链接素材、ICC/ICM、LUT 或其他打开/编辑依赖到 `交付/dependencies/`。
3. 删除规范化源图副本、语义清单、遮挡图、透明素材、蒙版、候选、背景、拆分总览、`design.json`、图层清单、预览、差异图、缓存、日志、全部报告及整个临时工作区。
4. 重新枚举 `交付/`：只允许一份 `final-layered.psd` 和可证明被 PSD 实际引用的依赖；无依赖时目录中只能有 PSD。
5. 失败、阻断或异常退出也必须清理本轮全部中间结果和半成品，只保留调用方原始输入。

## 13. 电商图专项规则

电商图尤其适合完整对象补全：

- 身体常被服装覆盖；
- 腿部常被短裤或裙子覆盖，并应在其下方自然延续；
- 袜子可能延续到鞋内；
- 上衣下摆与裤腰的前后关系必须根据当前图像判断；
- 背带、提手、袖子、包装翻盖和支撑件经常穿过其他对象后方；
- `directExtractionTargets`、Logo 和包装的原图可见像素属于保护区；`completionTargets` 以验收后的完整 Image 候选为最终像素依据。
- 同款服装的穿着展示、平铺展示、悬挂展示、前后视图和细节图必须各自作为独立实例；不得用“这是同一件衣服”作为素材复用理由。
- 当前穿着状态下的衣服、领带、背带、玩偶挂带和品牌标识应按画面证据形成完整移动单元，不能遗漏，也不能为了便于分割无依据拆开。

存在其他视角原图时，应优先使用真实视角补齐隐藏内容，再考虑生成模型。即使生成结果合理，隐藏商品结构仍必须标记为推测内容。

## 14. 已知失败模式与强制纠正

以下规则不是案例坐标特例，而是所有新案例都必须执行的通用防错流程：

| 失败表现 | 根因 | 必须在何处阻断 | 强制纠正 |
| --- | --- | --- | --- |
| 对象只剩局部，缺少背带、挂带、动作线或其他可见部件 | 只看主连通块或最紧蒙版 | 可见蒙版门禁 | 用 `attachedComponents`、原图连续性和多候选分歧确认缺失后，只执行一次“主体核心 + 完整外沿”SAM 补齐 |
| 对象白边、描边或柔边被吃掉，但紧边指标很好 | 把粗 ROI 当硬裁刀，或候选排序偏好面积更小 | AI/SAM 提示与非对称轮廓门禁 | 扩展搜索走廊并沿完整外沿增加正提示；对象零缺失、其他对象零泄漏即可，额外底层背景允许；禁止再次收紧和事后手工补边 |
| 两个完整图形彼此分开，却仍对每个图形内部执行补全 | 在识别完整对象前把内部排版或图案叠放误判为遮挡 | 遮挡资格门禁 | 先识别完整对象，只对不同对象之间已证实的 `occludes` 边生成 `completionTargets`；目标为空时禁止调用 Image 模型 |
| 没识别到透明字，却仍对其下方上衣执行 Image | 先猜测补全目标、后补遮挡理由，遮挡边没有合法前景节点 | 首轮识别与遮挡引用门禁 | `occludes.front` 必须引用已登记并验收的前景实例；身份不明的覆盖痕迹标记 `unresolvedOcclusion` 并阻断，无合法边则对象只走 `directExtractionTargets` |
| 同一件上衣生成两张或多张 Image 候选并同时进入结果 | 按遮挡边数量创建任务，或未约束同实例活动任务 | Image 任务注册门禁 | 任务按去重 `completionTargets` 创建；多个前景 Alpha 合并，同一实例只允许一个活动任务和一个接受结果 |
| 有遮挡对象未做源图可见像素 SAM 就直接生成 | 缺少当前实例的形态与归属证据 | 可见证据门禁 | `samVisibleTargets` 必须等于全部实例；有遮挡对象保存唯一一份 `visible_only` SAM/Matting 中间证据，用于提示和验收，但不得进入 PSD |
| Image 已生成完整对象后又做第二次 SAM/语义抠图 | 把源图可见残片或第二次模型误差重新施加到完整候选 | 补全 Alpha 门禁 | Image 前已有的 `visible_only` SAM 只锁定源 RGB；候选验收后不再跑第二次 SAM，完整候选 Alpha 决定隐藏轮廓 |
| 用灰色、背景色或模糊块填遮挡区域 | 把占位可视化当成图像补全 | 补全门禁 | 每个实例独立调用图像编辑模型，保存键色转 Alpha 后的完整连续候选对象层 |
| 被遮挡对象在 PSD 中同时出现生成层和源图可见层 | 把中间 SAM 证据误当成交付素材 | 单层交付门禁 | `completionTargets` 每个实例只能有一个像素层，且必须等于去背景后的完整 Image 候选 |
| 完整 Image 候选进入 PSD 后只剩洞口碎片 | 用隐藏支撑或 SAM 可见蒙版再次裁剪完整候选 | 完整生成层门禁 | `generatedCompleteAsset.alpha == candidateAlpha`；禁止与 `hiddenAlpha`、遮挡蒙版或可见残片求交 |
| 背景出现人物、服装、阴影或色块残影 | 把未知残余强制归给背景，或恢复蒙版越界 | 残余归属与背景门禁 | 未归属像素保持阻断；背景只在恢复蒙版内重建并逐对象移开检查 |
| 同款商品在另一位置被直接贴用 | 把商品家族误当成图像实例 | 实例独立门禁 | 先判定穿着/展示状态、视角、姿态和形变；每个实例独立分割、补全和验收 |
| 标题、副标题或装饰字成为图形层，或同一文字同时出现原生层与栅格层 | 把源外观/艺术字截图当成交付图层 | 文字门禁 | 每个字符串和实际放置位置只交付一个原生文字层；源外观仅可作为同层内部缓存，禁止独立字形图层 |
| 衣服、领带或其他一体搭配被无依据拆散 | 为分割方便破坏语义移动单元 | 语义清单门禁 | 以当前展示逻辑建立完整父对象，只在确有独立编辑价值时建立子层 |
| 半透明品牌字、注册标记或商品标签消失 | OCR 只扫描高对比文字 | 语义/OCR 与文字门禁 | 扫描低对比、半透明和跨材质内容；可识别字符串按每个位置建立唯一原生文字层，只有真实非文字符号才可建立透明栅格图形层 |
| PSD 可打开、与 design 一致就宣布完成 | 机械结构检查替代了语义和局部视觉检查 | 最终交付门禁 | 同时要求实例独立、局部轮廓、可见像素、附着部件、移开状态和透明品牌内容全部通过 |

发现新的失败类型时，先归因到“输入、实例身份、语义、分割、遮挡、补全、背景、文字、组装或导出”中的一个阶段，再增加通用证据与阻断规则；禁止用当前图片坐标、某个具体形状或某个案例编号写永久补丁。
