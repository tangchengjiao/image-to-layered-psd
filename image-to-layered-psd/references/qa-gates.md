# 阻断式质量门禁

除非用户明确修改验收契约，以下门禁全部必须执行。某一项得分很高，不能抵消另一项失败。

门禁按阶段执行，验收通过后才允许进入下一阶段。SAM 边界阶段固定为一次收紧调用；只有确认缺失的对象允许追加一次完整外沿补齐，补齐后不再重试。不能把上游错误带入补全、组装或 PSD 导出后再集中返工。

## 1. 输入与可追溯性

- 当前案例在任何视觉读取前已完成无查看清场；只保留明确指定的当前原图和用户真实参考，旧 `design.json`、PSD、语义计划、素材、蒙版、预览、中间证据、日志和报告均未保留。
- `run-initialization-report.json` 存在且通过；`oldArtifactsOpened == false`、`oldArtifactsRetained == false`、`oldArtifactsBackedUpOrMoved == false`、`otherCasesInspected == false`，并记录仅路径级的删除清单。
- 旧产物没有被改名、归档、复制到其他目录/案例、缓存到工作台或临时目录；无法证明时阻断。
- `processAuthority` 只包含本 skill 的 `SKILL.md` 与四份 references；README、设计方案、旧案例、旧报告、旧配置和脚本历史逻辑引用数为零。
- 原始源图存在且保持不变。
- 规范化参考图的尺寸和方向正确。
- `input-evidence-manifest.json` 在任何视觉分析前生成且通过；允许证据只包含当前源图与用户明确提供的当前任务真实参考。
- 多模态、OCR、提示计划、SAM、Image 和验收报告的实际视觉输入哈希均属于 `allowedEvidence`；旧案例、旧结果、拆分总览、旧蒙版、旧 PSD 或派生 QA 图的引用计数为零。
- 记录源图、模型/检查点、提示计划、素材、`design.json` 和 PSD 哈希。
- 每个提取或生成元素都有明确来源类型。

## 2. 语义清单

- `object-integrity-plan.json` 已由多模态模型基于当前源图生成，先于任何分割和补全。
- `semanticPlanOrigin == "current_source_fresh_analysis"`、`copiedFromPriorCase == false`，且对象键、数量、坐标、提示词和层级没有从旧案例计划继承。
- `object-integrity-plan.json` 的当前版本哈希在 SAM 前冻结；同一版本的收紧和单次补齐报告引用同一全局计划哈希与对象级语义契约哈希，且没有改变对象身份、组成部件、组件归属、父子/互斥/遮挡关系或 `backToFront`。SAM 证据要求修改语义时已阻断旧版本、生成新版本并通过增量重启门禁，未在活动计划内静默改写。
- 顶层 `instances` 全部是完整移动对象，组成部件只嵌套于所属实例。
- 已在任何对象级 SAM/Image 调用前把 `occlusionEdges`、包含全部已登记节点且无重复的 `backToFront`、`samVisibleTargets = instances`、`completionTargets = unique(occludes.behind)` 与 `directExtractionTargets = instances - completionTargets` 写入并冻结在 `object-integrity-plan.json`。
- `samVisibleTargets` 与完整实例键完全一致；`completionTargets` 是其合法子集，`directExtractionTargets` 与 `completionTargets` 互斥且覆盖全部实例；内部领带、袖子、背带或挂带没有另行输出。
- 默认 `reconstructionMode` 为 `semantic_complete_layer`，无遮挡对象为唯一的 SAM/Matting 原图完整层，被遮挡对象为唯一的完整 Image 候选层；若用户明确选择其他生成式重构模式，则使用独立模式和报告，不能通过本门禁。
- 所有可独立操作的对象和可编辑文字都已识别。
- 对象足够细，但没有破坏语义完整性。
- 完整肢体、服装、商品、人物、贴纸及其附着功能部件没有被误拆成碎片。
- 商品印花和纹理没有被误识别成营销文字。
- 视觉语言复核同意对象清单；存在无法消除的歧义时必须阻断。
- 每个实例的穿着状态、展示状态、视角、姿态形变、附着部件和复用策略均已明确。
- 低对比、半透明、重复和跨材质覆盖的文字、Logo、品牌标签与注册标记均已登记。
- `brandCoverageCheck` 已通过整图与多尺度切片复核，疑似品牌放置数与登记数一致，未登记残留为零；任何透明品牌字漏检都直接阻断首轮计划。
- 疑似覆盖痕迹没有处于“前景身份未识别但继续执行”的状态；`unresolvedOcclusions` 非空时首轮计划失败并停止。

内部组件候选、失败候选和 `passed: false` 的预览不得进入用户可见拆分总览、`design.json` 或 PSD。完整实例尚未形成时直接修正提示和对象计划，不能依赖最终门禁替代正确执行。

## 2.1 实例独立与禁止复用

- 每个实际出现位置有唯一 `instanceId`，默认 `reusePolicy: "forbidden"`。
- 穿着与未穿着、平铺与人体、正反面、整体与细节、不同姿态/透视/褶皱/遮挡关系均为独立实例。
- 不同实例未共享可见素材 URI、像素哈希、Alpha 哈希、蒙版、隐藏证据范围、完整补全素材、生成任务 ID 或候选 ID。
- 感知哈希或 Alpha 形状异常相似时已生成差异图并复核；状态不同却结果相同直接失败。
- 只有源图像素级重复且证据、变换、差异图和审批记录完整时，才允许 `proven_identical` 复用。
- 计算时间、模型调用成本、同款商品或“看起来差不多”均不是复用理由。

## 3. 全部对象的源图可见像素提取

- SAM 分割报告的 `targetKeys` 与 `samVisibleTargets` 及全部完整实例键完全一致；每个对象恰好有一份源图可见像素结果。
- 若本轮发生语义修订，`sam-revision-plan.json` 已通过：`affectedSamTargets` 与 `reusedSamTargets` 互斥且并集等于当前全部目标；删除目标的旧结果已作废；变化对象、变化遮挡边端点、目标分类变化者及提示/竞争/排除/所有权/遮挡支持受影响的传递闭包均已重跑。
- 每个复用对象都具有完整的同运行复用证明：源图/规范化/坐标、模型/检查点/编码、对象级语义契约、提示、竞争集合、排除输入、`scope` 和像素所有权均未变化，并针对新计划重新通过完整性、互斥与零泄漏检查。任何字段缺失时已经回退为重跑；禁止复用旧运行或其他案例结果。
- 受影响对象均读取原始全分辨率源图；局部 ROI 只限制搜索，不是裁切输入或最终 Alpha 硬边。只有编码缓存键完全一致时复用了 SAM2 全图编码。
- `directExtractionTargets` 的结果标记 `complete_from_source`；`completionTargets` 的结果标记 `visible_only`，只锁定原图真实像素，不声称恢复隐藏轮廓。
- 每个对象通过可见像素归属、轮廓连续性和原图连续性检查。
- 非对称轮廓门禁通过：`objectOmissionPixels == 0`，`foreignObjectLeakPixels == 0`；对象描边、白边、投影、尾巴、细线和柔边均属于必含内容，不能用更紧的 Alpha 或更高模型分抵消缺失。
- 多提取只要全部属于最底层背景即可接受；`backgroundHaloPixels`、`backgroundHaloMaxWidthPx` 与背景所有权证据已记录，余量未包含任何其他对象、文字、装饰或前景实例。背景余量的面积和宽度不单独构成失败或再次收紧理由；无法证明所有权时直接失败。
- 粗框、粗多边形和 ROI 没有作为硬裁刀截断 SAM 候选；候选选择先比较对象零缺失和其他前景零泄漏，再比较背景余量、边缘质量与模型分。
- 每个实例 `tightPass.callCount == 1`；紧候选完整时 `recallPass.callCount == 0`，紧候选缺失时 `recallPass.callCount == 1`。不存在第三次 SAM、循环扩边或事后像素补丁。
- `semanticInvariant.objectIdentityPreserved`、组件召回/归属、父子、互斥、遮挡及层级一致性全部通过；任何一种边界策略都没有改写首轮 AI 的对象及组成关系。
- 所有原图可见语义部件都已保留。
- 不含邻居或背景泄漏。
- 细小结构和语义相关的分离部件没有被误删。
- 多候选分歧低于阈值，或已完成明确复核。
- 以 100% 尺寸查看时不存在明显白边、黑边、硬锯齿或吃边。
- 透明素材四边均接触非零 Alpha，不存在透明留白。
- `attachedComponents` 中的背带、提手、挂带、动作线、玩偶附件、纽扣、标签和透明品牌内容逐项存在。
- 所有 `mutuallyExclusiveWith` 检查均通过；不同实例的交付 Alpha 不共享源像素，也没有把相邻对象的同色细长部件误并入当前实例。衣服肩带与玩具绳等易混组件必须按端点、走向和连接对象分别验收。
- 重跑与复用结果合并后，已对当前全部实例重新执行全局像素所有权、前景泄漏、遮挡图、目标集合和可见 Alpha 并集检查；没有因局部重跑留下陈旧蒙版。目标 SAM、目标分类、遮挡边或 `frontOccluderSupport` 输入变化的 Image 结果已作废，前景并集变化时背景已重建，design、PSD 与最终全局 QA 已重新生成。
- 未归属残余像素没有按距离强制塞给最近对象；存在无法确认归属的像素时报告失败。
- 已通过的对象可见 Alpha 及文字/透明图形 Alpha 已冻结；可见 Alpha 用于锁定原图 RGB，前景层 Alpha 用于形成更深对象的 `frontOccluderSupport`。

不能只看缩小的拆分总览。必须检查原图叠加图和实际像素尺寸的独立素材。

## 4. 遮挡图

- 遮挡判断的输入是已经通过的完整语义对象清单，不是任意局部色块、文字、图案或对象内部子层。
- `contains`、`attachedTo`、印花、对象内部排版、边界接触和包围框重叠没有被误写成 `occludes`。
- 每条 `occludes` 关系都有图像或语义证据和置信度。
- 每条 `occludes.front` 都能解析到已登记并验收的实例、图形或透明文字键；不存在为了触发补全而虚构或悬空的前景节点。
- 透明品牌字未被识别时，没有仅凭其疑似痕迹把下方上衣送入 Image；若痕迹确实存在但身份未决，流程已在首轮识别阶段阻断。
- `object-integrity-plan.json` 在任何 SAM/Matting 前已经写入并冻结 `occlusionEdges`、`backToFront`、`samVisibleTargets`、`completionTargets` 和 `directExtractionTargets`。
- `completionTargets` 与全部 `occludes.behind` 节点的去重集合完全一致，没有额外对象。
- `samVisibleTargets = instances`，`directExtractionTargets = instances - completionTargets`；`occlusion-graph.json` 与首轮计划逐项一致，只是派生快照，没有在 SAM 后重算层级。
- 遮挡图无环，`backToFront` 是合法拓扑顺序。
- PSD 图层顺序与遮挡图一致。
- 真实前后交错通过最少子层表达，并继续保留完整语义父对象。

## 5. 被遮挡对象补全

- 只有 `completionTargets` 中的对象进入补全；每个目标要么完成补全，要么明确阻断。
- `completionTargets` 为空时，`imageEditRequired` 为 `false`、`imageEditCallCount` 为零、`objects` 为空，没有创建补全素材或占位图层。
- 任何图像编辑调用都能追溯到已通过的 `occludes` 边；不存在“先补全、后找遮挡理由”。
- 每个补全目标在 Image 前已经有且只有一份 `visible_only` SAM/Matting 中间证据，用于提示与验收候选；该证据没有进入 PSD。
- Image 任务数按去重后的 `completionTargets` 计算，不按遮挡边数计算；同一实例没有两个活动任务或两个接受结果。
- 同一实例被多个前景对象覆盖时，使用这些已验收前景 Alpha 的并集作为一个 `frontOccluderSupport`，只补全一次。
- 候选通过状态与组成检查后只执行一次确定性 Alpha 转换/规范化，`alphaConversionCount == 1`。
- 接受候选后未再次执行第二次 SAM、语义抠图或用源图可见残片蒙版裁剪，`semanticSamCallCountAfterCandidateAccepted == 0`。
- `candidateAlpha` 是被遮挡对象完整轮廓的唯一依据，没有被二次提取结果替换。
- `generatedCompleteAsset = generatedCandidate ∩ candidateAlpha`，且 `generatedCompleteAsset.alpha == candidateAlpha`；除键色边缘去色外 RGB 与接受候选一致，完整生成素材没有再与任何中间蒙版或源图可见残片求交、覆盖或拼贴。
- 每个生成素材单独显示时是一张连续完整对象，不是只剩遮挡洞口的碎片集合。
- 每个 `completionTarget` 在 PSD 中恰好只有一张交付像素层，并且就是 `generatedCompleteAsset`；不存在源图可见层或补丁层。
- 每个实例使用独立图像编辑任务，没有复制、缩放或变形另一实例的补全结果。
- 补全不是中位色、纯灰、纯背景色、模糊色块或手绘占位。
- 补全与可见对象的结构、材质、纹理、光照和透视连续。
- 没有生成缺乏真实来源的文字、Logo、标签、包装信息或身份关键细节。
- 恢复原始坐标和层级后，单一完整生成层仍按首轮 `backToFront` 位于遮挡者后方。
- 生成层明确标记为推测，并记录模型、版本、提示词和置信度。
- 合成破洞、错位或错误露出时先修复坐标、支持区域、遮挡蒙版与层级；只有候选自身状态/视角/姿态/组成失败时才重新生成。

## 6. 背景

- 恢复范围外的已知背景像素保持不变。
- 移除前景后不存在可识别的对象残影、描边、阴影或补丁边界；真正属于背景的阴影除外。
- 补全区域与周围透视、纹理、颜色和光照连续。
- 背景恢复蒙版和生成来源完整存在。
- 未归属前景残片没有被强制写入背景。
- 每个对象单独移开后均已检查，背景没有残留前景颜色、透明字、轮廓、阴影或补丁边界。

## 7. 文字与形状

- OCR/原图、`design.json` 与 PSD 原生文字内容 Unicode 完全一致。
- 用户编辑内容保持原样；不得翻译、自动规范化、裁空格、改变大小写、修改标点或换行。
- 字体 PostScript Name 和字体哈希已记录；缺失或近似字体按任务规则列为警告或阻断。
- 文字没有意外溢出或裁切。
- 可可靠恢复的简单形状使用原生形状层；栅格化降级必须明确记录。
- 每个实际字符串和放置位置独立建层，没有把整片排版合并为一个大栅格块。
- 可编辑营销文字、标题、副标题和艺术字均为唯一原生文本框；包含其字形的独立栅格层、图片层、图形层和效果子层数量必须为 0。源外观缓存只能附着于同一个原生文字层，不能出现在图层树、PSD 图层列表或画布可选对象中。非文字装饰图形已单独登记。被文字遮挡的图形已按完整对象补全门禁验收，而不是只保存露出的碎片。
- 逐个关闭文本框并检查其缓存/图层内容：只能消失该字符串，不能连带出现或消失蝴蝶、阴影、背景、其他文字或任何相邻图形；文本缓存跨实例污染像素数必须为 0。
- 覆盖式透明品牌标签、Logo、注册标记、服装印花和实体标签均按正确类别、位置、透明度与层级保留。

## 8. design.json

- Schema 校验通过，且没有禁用字段。
- 元素 ID 唯一，所有引用可解析。
- 素材尺寸、哈希和位置与文件一致。
- 图片使用不规则 Alpha，不是带不透明背景的大矩形。
- 分组、层级、显隐、透明度、混合模式、文字、蒙版、置信度和复核标记完整。
- 语义清单、遮挡图和补全报告与图层树一致。

## 9. PSD 结构

- PSD 存在、非空，并能被写入库回读器和独立解析器解码。
- 画布尺寸、颜色模式、DPI、根组、总图层数、名称、顺序、显隐和分组符合能力计划。
- 图片层保留透明通道。
- 必需文字仍是原生文字层，内容逐字一致。
- 每个可编辑字符串在 PSD 中恰好对应一个文字层；不存在同字形的像素/图形交付层。
- AI 补全层与原图提取层可以明确区分。
- 不支持效果已栅格化并报告，而不是静默丢失。

## 10. 像素对比

分别执行以下对比：

1. `PSD 合成预览 ↔ design 参考图`：原则上必须逐像素一致；存在容差时必须由导出契约明确解释。
2. `PSD 回读图层合成 ↔ design 参考图`：遵守相同规则。
3. `全部对象原位重合成 ↔ 规范化源图`：生成差异图并验证组间首轮层级；完成对象允许因完整 Image 候选与源图不同而产生差异。
4. `directExtractionTargets 原图像素 ↔ SAM完整提取层`：除声明的 Alpha Matting/颜色净化边缘带外必须一致。
5. `completionTargets 接受候选 ↔ PSD单一完整透明层`：Alpha 必须一致，RGB 除键色边缘去色外必须一致，且像素层数量必须为一。

前两项即使完全一致，也不能证明分割正确，因为 design 和 PSD 可能以同一种方式“完全一致地拆错”。

全局相似度、PSD/design 一致或文件可打开，都不能替代实例状态、局部轮廓、附着部件、透明品牌内容、背景移开状态、直接提取对象的源像素检查和完成对象的单层候选一致性检查。
