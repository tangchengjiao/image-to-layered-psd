# 使用教程

## 1. 准备输入

提供一张明确的当前源图、一个本次专用案例目录和 PSD 实现项目目录。参考图、输出尺寸、字体要求、重点保留对象可一并说明。不要仅提供包含许多候选图片的文件夹，让 Agent 猜测哪个是源图。

建议将原始材料放在案例目录之外：

```text
<工作区>/
├── originals/poster.png           原始图片
├── PSD智能工作台/                 已配置的实现项目
└── 电商图/案例001/                本次专用案例目录
```

原 Skill 的生产规则会清理当前案例的旧派生产物，完成后也会清理本轮中间文件。不要将其他项目、已有交付或需要长期保存的材料混入该专用目录。

## 2. 先检查实现环境

首次接入可以直接发送：

```text
读取 $image-to-layered-psd 及四份 references。
本次只检查环境，不处理图片、不删除文件。
实现项目：<实现项目绝对路径>
请核对语义识别/OCR、SAM2/Matting、图像编辑、字体、PSD 导出与回读模块，
列出已存在的入口、缺少的实现，以及原项目路径需要如何映射。
```

本仓库没有安装上述依赖的统一命令。原文中的案例命令只适用于对应原实现项目，具体对接见[实现说明](IMPLEMENTATION.md)。

## 3. 发起分层任务

实现准备好后，使用以下模板并替换路径：

```text
使用 $image-to-layered-psd 将这张海报重建为分层 PSD。

源图：<当前唯一源图的绝对路径>
参考图：<明确指定的参考图路径；没有则写“无”>
实现项目：<PSD 实现项目绝对路径>
案例目录：<本次专用案例目录绝对路径>

要求：保留全部原文；商品、装饰与背景可独立操作；
文字使用原生文字层；按实际遮挡关系补全对象；
执行 PSD 回读与逐对象移开检查。
完成后交付 final-layered.psd 及实际必需外部依赖，
并说明生成内容、文字效果限制和验收结果。
```

## 4. 理解生产过程

1. 识别完整对象、所有字符串、组成关系与遮挡关系，确定前后层级。
2. 使用 SAM2 / Matting 提取可见像素，检查对象完整性和透明边缘。
3. 对对象间实际遮挡的目标生成完整透明对象，分别核对形态与归属。
4. 恢复背景、重建文字并组装临时设计数据。
5. 导出 PSD，回读图层与文字，逐个移开对象检查补全和背景。
6. 完成验收后交付 PSD 与必需依赖，清理临时数据。

详细执行规则以 [SKILL.md](../image-to-layered-psd/SKILL.md) 和四份参考文档为准。这份教程用于上手，不替代生产规范。

## 5. 接收与检查交付

预期交付结构：

```text
交付/
├── final-layered.psd
└── dependencies/                  仅在确有必需外部依赖时存在
```

打开 PSD 后核对：图层名称与分组是否清晰，文字是否可编辑，移动商品后背景有无残影，被遮挡对象是否完整，细小附着部件是否保留，以及原图与重建合成的主要差异。

原 Skill 不将临时 `design.json`、蒙版、预览或 QA 报告作为最终交付；执行 Agent 应在最终回复中说明检查结论和局限。Skill 分发 ZIP 内的使用文档与“PSD 生产交付目录”是不同用途。

## 常见问题

**安装后为什么没有“一键生成”按钮？** 这是 Agent Skill，包含工作流和接口规范。实际图像处理与 PSD 写入由接入项目提供。

**所有图层都能编辑吗？** 原生文字层可修改文字；透明像素层可移动、隐藏和像素编辑。商品不会自动变成三维模型，复杂印花也不会自动变成参数化矢量。

**能恢复商品被遮挡部分的真实细节吗？** 单张图没有这部分原始信息。补全使用生成模型推测，涉及商品细节时需要人工复核。

**没有对象间遮挡，还会补全对象吗？** 按规范应跳过对象补全。背景恢复是否需要图像编辑，仍取决于背景缺失情况。

**缺少字体或导出器不支持某些效果怎么办？** 先补齐可用字体和实现能力；仍有局限时明确说明近似或缺失效果，不能将栅格文字冒充原生可编辑文字。

**仓库里有可直接执行的 Python 或 Node 命令吗？** 没有。参考文档提及的脚本属于外部实现项目，仓库没有附带这些程序。
