## 原项目映射怎样理解

[project-implementation.md](../image-to-layered-psd/references/project-implementation.md) 保留原作者的本机实现路径、案例目录及脚本名。这些是对接线索，不是已经随包安装的文件，也不应要求其他用户在本机创建相同盘符。

| 原文提到的入口 | 迁移时需要找到或实现的功能 |
| --- | --- |
| `generate_case3_sam2_masks.py` | 语义实例对应的 SAM2 可见像素分割 |
| `decompose_case3.py` | 透明素材、文字、背景和设计数据组装 |
| `validate_case_design.py` | 设计数据、素材引用和文字检查 |
| `export_layered_psd.mjs` | 设计数据到 PSD 的写入 |
| `validate_psd_roundtrip.py` | PSD 独立解析与导出回读 |
| `reconstruct_image_to_psd.py` | 原文提出的通用执行器形式，包中未提供 |

原文指出，已有案例骨架主要覆盖可见对象拆分，不能据此宣称通用遮挡补全已经实现。对接时逐项核对实际代码与规范的差距。

## 建议接入顺序

1. 确定实现项目、输入源图、专用案例目录和输出目录的本机映射。
2. 阅读全部规范，建立对象、文字、遮挡关系和图层数据接口。
3. 接通可见区域提取，再接入需要补全的对象与背景生成。
4. 实现原生文字与 PSD 写入，使用独立解析器检查生成文件。
5. 用当前测试图验证移动对象、背景和文字效果，再决定是否具备正式交付能力。

原包保留了案例清理与中间文件清理规定。实际程序应将处理范围绑定到明确的专用案例目录，并遵守所在项目的权限与目录约束。上传 Skill 文档不代表执行其中的生产、删除或案例命令；本次发布未运行这些操作。
